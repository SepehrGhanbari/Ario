# ARIO INTEGRITY GATE V1 — RESEARCH_ONLY

این بسته را در پوشه‌ای جدا از آریو و آرشیوهای دریافتی استخراج کنید. از نسخه‌ای استفاده کنید که خودتان از منبع مورد اعتماد دریافت کرده‌اید؛ اجرای تأییدکننده‌ای که همراه فایل ناشناس آمده، اعتماد مستقل ایجاد نمی‌کند. Python 3.10+ و برای Clone، Git لازم است. هیچ کتابخانهٔ خارجی لازم نیست.

## اجرا در ویندوز

روی `RUN_INTEGRITY_GATE.cmd` دوبار کلیک کنید. شمارهٔ 1 ابتدا یک Clone تازه از کامیت ثابت رسمی `89ef7ba466db2e7a267ee7780df348ee9e5920e6` می‌گیرد، 473 فایل (96,396,968 بایت) را با درخت GitHub تطبیق می‌دهد و فقط اگر تطابق کامل باشد، ممیزی M0 با یک ورودی کاملاً ساختگی و بدون ledger را اجرا می‌کند. نتیجهٔ معرفتی مورد انتظار همان UNKNOWN است، نه PASS. این گزینه صریحاً اجرای آزمایشی سورس رسمی را درخواست می‌کند؛ محیط OS sandbox نیست. گزینهٔ 4 فقط Clone و بررسی می‌کند و هیچ کد دریافتی را اجرا نمی‌کند.

شمارهٔ 2، ZIP انتشار 11 نوامبر را خودکار دریافت، SHA-256 را با R1.4 تطبیق، و 204 فایل منبع را در یک پوشهٔ تازه بازیابی می‌کند. سپس فایل‌های بازیابی‌شده را دوباره با کامیت منبع `05ba5c960aaea96fc6bb80504b53b4d47e7d42f5` و درخت `8a9429d396c09fe17682a61dd91cb43672d3cb79` بررسی می‌کند. اسکریپت‌های تاریخی داخل ZIP اجرا یا استخراج نمی‌شوند. گزینهٔ 3 همین بررسی و بازیابی را برای ZIP یا TXT محلی همان انتشار انجام می‌دهد. برای TXT، manifest رسمی نیز دریافت و بررسی می‌شود. گزینه‌های 5 و 6 بررسی خواندنی Clone موجود یا فایل‌های یک رکورد DOI از فهرست 15تایی هستند. کل تاریخچه یا سایر نسخه‌ها خودکار پوشش داده نمی‌شوند.

پس از اجرا، فایل تازه‌ای با نام `INTEGRITY_GATE_RESULTS-*.json` کنار بسته ایجاد می‌شود. این گزارش ممکن است مسیر محلی داشته باشد؛ برای انتشار عمومی آن را جداگانه پاک‌سازی کنید. Exit 0 یعنی آماده‌سازی در محدودهٔ تعیین‌شده موفق بوده؛ Exit 2 یعنی رد؛ Exit 3 یعنی UNKNOWN. فقط مسیر اعلام‌شده در یک گزارش موفق، خروجی آماده‌شده است. فایل‌های باقی‌مانده پس از قطع برنامه یا خطای پاک‌سازی را استفاده نکنید.

## مرزها

- ابزارهای مورد استفاده، دقیقاً همان بایت‌های پذیرفته‌شده در PR #357 و R1.4 هستند. هیچ فایلی از مخزن اصلی یا آرشیو تاریخی تغییر نکرده است.
- ZIP/TXT در حافظه به صورت bytes نگه داشته می‌شود و همان بایت‌های دارای هش ثابت مصرف می‌شوند، نه خواندن دوبارهٔ مسیر ورودی بعد از تأیید. بازیابی مرحله‌ای با مقایسهٔ SHA-256 هر فایل و Git blob ID انجام می‌شود؛ فایل‌های خروجی سپس با درخت GitHub مقایسه می‌شوند. هیچ فایل موجودی جایگزین نمی‌شود.
- بررسی Clone به Git SHA-1 و محتوای فایل‌های کاری محدود است؛ .git، تاریخچه و modeها را تأیید نمی‌کند. برای کامیت‌های دیگر باید SHA دقیق را مشخص کرد. هیچ اثبات تازگی، هویت ناشر، نگهداری مستقل مرجع یا حقیقت محتوا وجود ندارد.
- این دروازه فقط مسیر رسمی جدید را کنترل می‌کند؛ اجرای مستقیم CLI قدیمی همچنان خارج از آن است. تغییر اجباری موتور و همهٔ entrypointها هنوز انجام نشده است. Clone عادی یا مرورگر به‌تنهایی هیچ کدی اجرا نمی‌کند.
- قطع شبکه، ناسازگاری داده، خطای تأییدکننده یا عدم تطابق باعث عدم ادامه می‌شود. کنترل OS، Python، Git، TLS و مسیرهای والد تحت فرض محیط مورد اعتماد است؛ حملهٔ هم‌زمان مدیر محلی، TOCTOU کلی، اجرای مخرب در OS یا قطع برق تضمین نشده‌اند. اجرای آزمایشی فقط ورودی مصنوعی دارد و هیچ مجوز اجرای عمومی صادر نمی‌کند. هیچ کلید، حافظهٔ فعال یا production فعال نشده است.

## شواهد

28 آزمون جدید در Linux موفق شد (TEST_RESULTS.log). 41 آزمون قبلی دوباره در بستهٔ اصلی پذیرفته‌شده اجرا و موفق شد (PRIOR_REGRESSION.log). آزمون‌های جدید از دادهٔ ساختگی و کنترل‌های mock برای شبکه، Git و شروع M0 استفاده می‌کنند؛ فایل‌های نمونه واقعاً نوشته و بازیابی شدند. یک اجرای زندهٔ بررسی checkout در محیط Linux به UNKNOWN رسید (live_probe.json). اجرای کامل واقعی startup/restore و ویندوز هنوز UNKNOWN است. برنامهٔ قدیمی درون آرشیو هرگز اجرا نمی‌شود.
