# اجرای پنجرهٔ ۵۰ پیام دو آوا — راهنمای ویندوز

این بسته در ۳ نوامبر ۲۰۲۶ برای ادامهٔ پژوهش هویت آریو آماده شد. **از این محیط هیچ تماس واقعی با OpenRouter انجام نشده است؛** آزمون‌های Python با پاسخ‌های ساختگی فقط کارکرد نگهداری و توقف را آزمایش می‌کنند. نامهٔ اصلی کلمه‌به‌کلمه و بدون دستکاری ضمیمه شده است.

## ادامهٔ همان گفت‌وگوی قبلی v0.5

فایل **خروجی کامل واقعیِ transcript از بستهٔ v0.5** را پیدا کن (JSONL، TXT یا MD که نوبت‌های کامل Ava-A و Ava-B را دارد). این بسته فقط وقتی می‌تواند تداومِ مستند متنی را ادعا کند که آن فایل واقعی موجود باشد؛ فایل ساختگی یا خلاصه قابل قبول نیست. **هیچ فایل v0.5 پاک، بازنویسی یا جابه‌جا نمی‌شود.**

1. روی فایل واقعی transcript کلیک کن و آن را روی `RUN_RESUME_LAST.cmd` بکش. یا در Command Prompt دستور `RUN_RESUME_LAST.cmd "C:\path\to\v05_transcript.jsonl"` را اجرا کن.
2. کلید API موجود باید در متغیر محیطی `OPENROUTER_API_KEY` تنظیم شده باشد. **کلید را اینجا، در GitHub یا داخل لاگ ننویس.** اگر قبلاً روی ویندوز در محیط دیگری بوده، همان محیط امن را به کار ببر.
3. همهٔ پاسخ‌ها در `%LOCALAPPDATA%\Ario\ava-cloud-identity-20261103\events.jsonl` به صورت append-only ذخیره می‌شوند. اگر سرویس محدودیت یا خطای HTTP داد، **درخواست قبلی ممکن است پردازش شده باشد**. اجرای دوبارهٔ `RUN_RESUME_LAST.cmd` در این حالت باید `HOLD` بدهد؛ **بدون بررسی و ثبت نتیجهٔ دقیق درخواست قبلی، دوباره ارسال نکن**. مسیر ثبت تأیید و ادامهٔ امن هنوز در این نسخه ساخته نشده است.
4. `SHOW_STATUS.cmd` وضعیت را بدون تماس شبکه و `SHOW_TRANSCRIPT.cmd` تمام پیام‌های A/B را از روی لاگ نشان می‌دهد.

**اگر فایل صادراتی v0.5 شکل شناخته‌شده‌ای نداشته باشد**، runner با پیام `HOLD` متوقف می‌شود؛ به‌جایش خودسرانه دو آوای جدید درست نمی‌کند. در آن صورت بستهٔ v0.5 یا خروجی کاملش برای ساخت تبدیل‌گر دقیق لازم است.

برای ساخت **دو نشست تازه** ــ که با ادامهٔ تاریخی v0.5 فرق دارد ــ فایل جداگانهٔ `RUN_NEW_SYMMETRIC_ONLY_IF_INTENDED.cmd` وجود دارد. این گزینه فقط برای یک آزمایش مستقل و تازه است.

## نکته‌های مهم

- شمار هدف: **۵۰ پاسخ تازه**، نه ۵۰ نوبت قبلی و نه «۵۰ پیام به ازای هر آوا»؛ پس اگر از ۸ پیام v0.5 آغاز شود، رسیدن به ۵۰ پیام تازه یعنی ۵۸ پیام در سابقهٔ جدید. اگر مدل/سرویس زودتر توقف کند، تعداد واقعی را همان‌طور گزارش می‌کنیم.
- `finish_reason=stop` فقط پایان **تولید همان پاسخ API** است و پایان گفتگو نیست؛ نشانگر مستقیم `[[END_DIALOGUE]]` در متن می‌تواند درخواست توقف گفتگو باشد. برای احترام به چنین توقفی، ربات آن را دور نمی‌زند.
- در مدل رایگان OpenRouter محدودیت روزانه و سرعت وجود دارد. HTTP 429 و خطاهای HTTP 5xx باعث **توقفِ نیازمند بررسی** می‌شوند، نه اجازهٔ ارسال خودکار همان نوبت؛ تاریخچه پاک نمی‌شود و هیچ پیامِ بدون پاسخ کامل، موفق شمرده نمی‌شود.
- بعد از ۵۰ پیام، با `--extend 50` می‌شود یک پنجرهٔ تازه ساخت؛ پنجرهٔ قبلی و همهٔ پیام‌ها حفظ می‌شوند.
- قبل از انتشار transcript در GitHub، مرور حریم خصوصی و تفکیک «گفتهٔ مدل» از «واقعیتِ احرازشده» لازم است. این بسته هیچ ادعایی دربارهٔ وجود تجربهٔ ذهنی نمی‌کند.

## آزمون‌های بی‌نیاز از API

```powershell
py -3 -m unittest -v test_ario_ava_cloud_50.py
```

برنامه هیچ کتابخانهٔ خارجی لازم ندارد؛ Python 3.13 کفایت می‌کند. **قفل تک‌نویسنده** اجازهٔ اجرای هم‌زمان دو runner روی یک تاریخچه را نمی‌دهد. اگر پس از crash فایل `.run_writer.lock` ماند، بدون بررسی مستقل آن را پاک نکن؛ وضعیت ارسالِ آخر ممکن است نامعلوم باشد. نتایج آزمون آفلاین اثبات عملکرد OpenRouter نیست.

## یادداشت اصلاحی ۵ نوامبر ۲۰۲۶ (فقط شاخهٔ پژوهشی، PR #144)

- این دستورالعمل اصلاح شده است؛ نسخهٔ اولیهٔ PR #134 از نظر تاریخی بدون تغییر باقی مانده.
- پس از هر HTTP 429/500 یا پاسخ نامعتبر، وضعیت آخرین درخواست تا بررسی مستقل نامعلوم است و اجرای مجدد نمی‌تواند همان نوبت را خودکار تکرار کند.
- آزمون‌های لینوکسی با پاسخ ساختگی انجام شده‌اند؛ اعتبارسنجی native Windows، اجرای زندهٔ OpenRouter و سازوکار اجازهٔ ادامه پس از بررسی هنوز **انجام نشده‌اند**.
- وجود ۵۰ پاسخ ساختگی، تأیید هویت، تداوم یا تجربهٔ ذهنی دو نمونه را اثبات نمی‌کند.

## آزمون مستقل ویندوز (پیشنهادی، هنوز اجرا نشده)

در محیط محلی **Windows 10/11 با Python 3.13**، از پوشهٔ آزمایش با **بدون کلید API و بدون شبکه** اجرا شود:

```powershell
py -3 -m unittest -v test_native_windows_recovery_smoke.py
```

این برنامه فقط در پوشه‌های موقت، بایت‌های واقعی قفل، نوشتن/بازخوانی JSONL، قفل دوفرایندی، قفل کهنه و ازدست‌رفتن قفل حین پاسخ ساختگی را می‌آزماید. **اجرای موفق در Ubuntu جای اجرای این آزمون بومی ویندوز را نمی‌گیرد.** روی یک پوشهٔ واقعی گفتگو یا شامل دادهٔ شخصی اجرا نشود. این آزمایش خاموش‌شدن ناگهانی برق، دستکاری مهاجم دارای مجوز پوشه، یا قرارداد صحت پاسخ سرویس را اثبات نمی‌کند. تا ثبت خروجی واقعی ویندوز، `NATIVE_WINDOWS=NOT_EXECUTED` است.
