# Issue #227 — bounded review candidate

Research-only. Legacy semantic identifiers and legacy trimmed event hashes remain unchanged. The opt-in report records both the legacy trimmed and raw-line SHA-256 for each completed nonblank line, without making the legacy hash an unambiguous inverse mapping. Duplicate raw representations are separate line entries. Reports contain linkable digests; do not export automatically. Keep original input bytes under existing retention policy; no new durable store is introduced.

`ledger_line_digests` defines the two named schemes: `legacy_trimmed_v0_1` is the only stored event identity; `raw_line_v0_2` is report-only. LF/CRLF/padded forms that share one legacy digest replay; they do not create a second semantic node and no inverse alias table is introduced. VT/FF are outside the legacy trim set.

The existing agent bridge already has a typed policy for goals and step reports and counts task finishes without triggering actions. The generic consolidator deliberately does not turn unmapped events into claims. The new report distinguishes newly ingested records, semantic-linking events, unmapped events, replay, and blank lines; semantic-linking counts events, not distinct graph nodes or truth. Success reports cover completed structurally valid batches only; errors do not emit a successful report. Blank lines retain legacy skip behavior; this is not a general parser equivalence claim.

Completed LF (including CRLF) is required for generic ingestion and for accepting a line during read-only integrity inspection. Ingestion rejects every unterminated line before parse or mutation. Inspection still reports an unparseable crash tail as CORRUPT_JSON_OR_TRUNCATED_TAIL with corrupt_line_no; HOLD_INCOMPLETE_JSONL_LINE is only a blank tail or a structurally acceptable record with no completed LF. The agent bridge rejects incomplete tails before applying any prefix, using a bounded read of the same bytes.

Bridge commits are atomic in-process: parse first, then apply under a checkpoint of engine, source guard (including active verification ids) and prospective registry; any failure restores the pre-call state. This is not a durable filesystem journal and does not import verification authority across process recovery. No evidence admission, task-completion inference, or trust activation. No history rewrite or numeric sidecar adoption.
