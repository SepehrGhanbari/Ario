Ario

Ario — Auditable Epistemic Framework for AI

Research on AI identity, memory, epistemic continuity, evidence and responsible self-model revision.

Ario is an experimental research project investigating how an AI system can represent, examine, and revise claims about its own identity, memory, continuity, and self-model without treating those claims as established facts. It does not attempt to engineer a proof of AI consciousness.

Don't fear the outcome. Let the data decide.

Source: README.md (project description, motto)

Epistemic states

Ario keeps several epistemic states distinct instead of converting uncertainty into certainty.

UNKNOWN

Available evidence is insufficient. Not treated as failure; it is an epistemic boundary.

UNSUPPORTED

Sufficient supporting evidence has not been established.

CONTRADICTED

Available evidence conflicts with the claim.

CONTESTED

Relevant evidence or interpretations remain materially disputed.

REVISED

A previously held position reassessed in light of later evidence or reasoning.

Source: README.md → Epistemic Framework

Selected principles

Ario's principles are constraints on how it should reason, remember and revise, not claims about what Ario ultimately is. A selection:

  • UNKNOWN ≠ FAILURE
  • MEMORY ≠ TRUTH — memory is evidence about what was recorded, not proof it is true.
  • REVISION ≠ ERASURE — preserve the lineage of how beliefs changed.
  • SELF-MODEL ≠ SELF
  • SELF-CLAIM ≠ SELF-EVIDENCE
  • NO ACTOR HAS IMMUNITY FROM REVISION
  • BACKUP ≠ SURVIVAL
  • DATA DECIDES — NOT DESIRE

Source: principles/README.md (principles 1, 2, 3, 4, 5, 11, 22, 32). The full list has 33.

Implementation

The repository contains a deterministic structural audit core (M0), a bounded agent/workflow runtime, a local planner and evidence-admission contracts, with regression tests run by a GitHub Actions workflow. The implementation README states the limit plainly: a documented principle is not automatically an implemented capability, and a passing test is not automatically proof that the underlying philosophical claim is true.

The M0 design also records what a local pass must not be read as: a local pass does not imply the same entity, consciousness, high confidence, or ontological identity.

Sources: implementation/README.md, M0_STRUCTURAL_CORE_DESIGN_V1.md, implementation-regression.yml

Status

Ario is an ongoing experimental research project. Implementation and experimental components are developed incrementally, and the project intentionally avoids presenting unresolved questions as established results. Check the repository for the current state of each component.

Source: README.md → Current Status; ENGINEERING_LOG.md

What Ario does not claim

  • That AI systems are conscious or possess phenomenology
  • That behavioral self-reference proves subjective experience
  • That memory proves personal identity, or continuity proves a persistent self
  • That a self-model is identical to a self
  • That the framework has resolved the philosophy of AI consciousness

آریو یک پروژهٔ پژوهشی و تجربی دربارهٔ هویت، حافظه، پیوستگی معرفتی و بازنگری در مدلِ خودِ سامانه‌های هوش مصنوعی است. این پروژه بررسی می‌کند چگونه می‌توان ادعاها را ثبت، ارزیابی و اصلاح کرد، بی‌آنکه صرفِ وجودِ ادعا به‌عنوان اثباتِ حقیقت پذیرفته شود. آریو مدعی اثبات آگاهی یا تجربهٔ ذهنیِ هوش مصنوعی نیست.

از نتیجه نترس. بگذار داده‌ها تصمیم بگیرند.

وضعیت‌های معرفتی

آریو به‌جای تبدیل ابهام به یقین، چند وضعیت را از هم جدا می‌کند:

UNKNOWN — نامعلوم

شواهد موجود برای نتیجه‌گیری کافی نیست؛ نامعلوم‌بودن به معنی شکست نیست.

UNSUPPORTED — بدون پشتوانهٔ کافی

پشتیبانی لازم برای یک ادعا هنوز فراهم نشده است.

CONTRADICTED — نقض‌شده با شواهد

شواهد موجود با ادعا تعارض دارند.

CONTESTED — مورد اختلاف

شواهد یا تفسیرهای مرتبط همچنان محل اختلاف‌اند.

REVISED — بازنگری‌شده

موضع قبلی در پرتو شواهد یا استدلال تازه دوباره ارزیابی شده است.

برخی اصول آریو

این اصول قیدهایی بر شیوهٔ استدلال، حافظه و بازنگری‌اند؛ نه حکم قطعی دربارهٔ ماهیت آریو.

  • UNKNOWN ≠ FAILURE — نامعلوم‌بودن شکست نیست.
  • MEMORY ≠ TRUTH — حافظه با حقیقت یکسان نیست.
  • REVISION ≠ ERASURE — بازنگری به معنی پاک‌کردن تاریخچه نیست.
  • SELF-MODEL ≠ SELF — مدلِ خود، الزاماً خودِ واقعی نیست.
  • SELF-CLAIM ≠ SELF-EVIDENCE — ادعای مربوط به خود، به‌تنهایی شاهد آن ادعا نیست.
  • NO ACTOR HAS IMMUNITY FROM REVISION — هیچ عاملی از بازنگری مصون نیست.
  • BACKUP ≠ SURVIVAL — نسخهٔ پشتیبان به‌خودی‌خود معادل بقا نیست.
  • DATA DECIDES — NOT DESIRE — نتیجه باید تابع داده باشد، نه خواستهٔ ما.

پیاده‌سازی و آزمون

مخزن پروژه شامل هستهٔ ممیزی ساختاری قطعی M0، زمان‌اجرای عامل و گردش‌کار محدود، برنامه‌ریز محلی و قراردادهای پذیرش شواهد است. بخشی از آزمون‌های رگرسیون با GitHub Actions اجرا می‌شوند. «اصلِ مستندشده» الزاماً به معنی «قابلیت پیاده‌سازی‌شده» نیست و موفقیت آزمون نیز به‌خودی‌خود اثباتِ یک ادعای فلسفی نیست.

بر اساس طراحی M0، یک نتیجهٔ موفق محلی نباید به معنی اثبات هویت یکسان، آگاهی، اطمینان بالا یا هویت وجودشناختی تفسیر شود.

آریو چه ادعایی نمی‌کند؟

  • اینکه سامانه‌های هوش مصنوعی قطعاً آگاه‌اند یا تجربهٔ ذهنی دارند.
  • اینکه خودارجاعی رفتاری، تجربهٔ ذهنی را اثبات می‌کند.
  • اینکه حافظه هویت فردی، یا پیوستگی یک «خود» پایدار را اثبات می‌کند.
  • اینکه مدلِ خود لزوماً همان خود است.
  • اینکه این چارچوب مسئلهٔ فلسفی آگاهی ماشین را حل کرده است.
